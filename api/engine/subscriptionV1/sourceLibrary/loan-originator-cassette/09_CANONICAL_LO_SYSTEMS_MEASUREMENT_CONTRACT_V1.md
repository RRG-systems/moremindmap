# Canonical LO Systems Measurement Contract V1

Authority ID: `loan-originator-systems-measurement-v1`

## Governing rule

**SYSTEMS HAVE NUMBERS. TOOLS ARE NOT SYSTEMS.**

A tool can support a system. Tool ownership alone cannot satisfy a system evidence mission.

## Minimum measured-system record

| Field | Minimum meaning |
| --- | --- |
| `who` | defined audience/segment and applicable network/business stage |
| `what` | repeatable action/workflow |
| `how_often` | cadence or trigger with period |
| `how_delivered` | channel and delivery method |
| `automation_personal` | personal, automated, or blended |
| `owner` | accountable actor and control scope |
| `leading_measure` | activity/output metric with definition/window |
| `observed_outcome` | compatible result measure when known |
| `review_window` | period used to evaluate the system |
| `stop_adapt_condition` | optional falsification/change condition |

The first four fields establish a repeatable system. Calling it a **measured system** additionally requires owner plus at least one governed leading measure. Outcome evidence strengthens but is not mandatory when the effect horizon is incomplete.

## Relationship-system quality

Customer-facing assessment should acquire enough structure to reason over:

`frequency × channel × relationship depth × audience/segmentation`

It must preserve:

- personal voice/face-to-face/handwritten/event activity versus automated email/text/digital touches;
- one-way versus two-way engagement;
- OSN versus CRN audience;
- applicable contact/use/compliance authority;
- source/relationship outcomes separately from raw activity.

No universal touch count is a score. 6×6/8×8, 25+/35+ Touch, 4–1–1, and Win-the-Day/Week/Month/Year remain optional heuristics requiring applicability, owner, evidence window, outcome measure, stop condition, and compliance review.

## Operating-system evidence

The same contract applies beyond relationships to:

- Opportunity intake/follow-up;
- Application/preapproval workflow;
- file coordination and handoffs;
- processing/underwriting/closing follow-up;
- customer communication;
- accountability/priority execution;
- evidence review and learning.

## Tool/system distinction examples

- “I use a CRM” → tool only; system evidence missing.
- “Every Tuesday my assistant sends the segmented past-customer list; I personally call ten people; we track conversations and Opportunities monthly” → measurable CRN system.
- “The company buys internet leads” → source/channel fact; follow-up system still unknown.
- “Processor handles files” → ownership fact; capacity/system quality still needs workload, handoff, service, and outcome evidence.

## Truth and projection

- Customer-described behavior is `OBSERVED` with customer-stated provenance.
- Activity/outcome ratios are `DERIVED` only from compatible windows.
- A proposed cadence is `SCENARIO` or Plan commitment.
- A heuristic comparison is `BENCHMARK`/prior, never observed system quality.
- Missing measures narrow Box 1 and Subscription context; they do not become zero execution.
